# SAMPLE_PACK

This folder is a long-lived **refactoring safety kit** for the bill-generation system.
It is designed so a new team can validate behavior without depending on tribal knowledge.

## Purpose

- Preserve representative **inputs** (with and without extra items).
- Preserve **reference outputs** from UNIF and current consolidated app.
- Preserve **evidence reports** (text similarity + visual diff metrics).
- Provide scripts to regenerate outputs and detect regressions quickly.

## Folder layout

- `01_inputs/` - Canonical sample Excel inputs.
- `02_reference_unif_outputs/` - Reference outputs generated from UNIF baseline app.
- `03_consolidated_outputs/` - Outputs generated by this repository.
- `04_ocr_and_quantity_text/` - OCR/image fixtures and quantity text snapshots.
- `05_reports/` - Certification summaries, diff reports, and run metadata.
- `scripts/` - Utility scripts to rebuild/verify this pack.
- `docs/` - Operational guides and conventions.

## Team workflow (recommended)

1. Add or update inputs in `01_inputs/`.
2. Run certification script from repo root:
   - `python tests/pdf_certification_harness.py --limit 9 --visual`
3. Copy selected stable outputs/reports into this folder (or run pack scripts).
4. Review `05_reports/summary.csv`:
   - watch for drops in text similarity
   - watch for visual diff spikes
5. If behavior change is intentional, update this pack and record rationale in `docs/CHANGELOG.md`.

## Acceptance checks (practical)

- Six templates per file should be generated (extra-items template may be absent only when both sides omit it).
- Text similarity should remain high relative to baseline for unchanged templates.
- Visual diff should stay within previously observed range for unchanged templates.
- Output readability and margins should not regress.

## Critical policy

- Do not delete base reference apps or test/input folders used for certification.
- Keep provenance metadata updated so this pack remains useful if external references move later.
